# EasyFlow 橋接

在**你自己的電腦**上幫忙填公司簽核單（EasyFlow）的小程式。

在數據網站上跟 Woby 說「幫我請 9/18 特休」，它就會在你電腦上開瀏覽器、登入 EasyFlow、把假單填好，然後**停下來等你自己檢查**。

> **它永遠不會替你按「送簽」。** 送出與否一律由你決定。

還可以查：**可休時數**、**請假記錄**、**刷卡記錄**。查過一次之後 Woby 就記得了，下次直接問就好。

## 給使用者：怎麼裝

1. 到 [Releases](../../releases) 下載 `EasyFlow-Bridge-win.zip`
2. 解壓縮到一個固定的地方（例如 `C:\EasyFlow-Bridge`）—— **不要放在「下載」資料夾**，之後每次都要用到
3. 雙擊 **`開始使用.bat`**（會閃一下黑窗，正常）
4. 視窗跳出來後填四個欄位：
   - 你在數據網站上登入用的 email
   - 授權碼（畫面上有「幫我開那一頁」可以直接跳到網站拿）
   - 你的 EasyFlow 帳號
   - 你的 EasyFlow 密碼
5. 按「檢查並儲存」，它會依序確認授權碼、瀏覽器、能不能登入 EasyFlow（約 20～30 秒，中途會閃一下瀏覽器，正常）

第一次跑完會自動在**桌面放一個捷徑**。之後點桌面那個就好，**連黑窗都不會閃**。

那個視窗要留著開（關掉就等於下線）。要用的時候開，不用的時候關。

> 如果之後換了一包新版本，記得**再點一次 `開始使用.bat`**（原因見下面）。

### 需要什麼

- Windows 10 / 11
- Edge 或 Chrome（Windows 內建就有 Edge，不用另外裝）
- 不用裝 Node.js —— 壓縮檔裡已經包好了

### 為什麼要先點那個 .bat（而不是直接點程式）

從網路下載的檔案，Windows 會打上一個「來自網際網路」的標記（Mark of the Web）。
**Windows 11 的 Smart App Control** 看到這個標記就會封鎖，跳「智慧型應用程式控制已封鎖此應用程式」。

實測結果：

| 檔案類型 | 帶著下載標記 |
|---|---|
| `.exe`（自己編的，沒簽章） | **被擋**，而且買憑證才有救 |
| `.vbs` / `.js` | **被擋** |
| `.bat` | **可以跑** ✓ |

所以入口做成 `.bat`：它不會被擋，跑起來第一件事就是**把整包的下載標記清掉**，
然後才把真正的程式（`EasyFlow_bridge.vbs`）叫起來。同事不用學「右鍵→屬性→解除封鎖」那招。

清完標記之後，桌面捷徑直接指向 `.vbs`，所以**平常啟動連黑窗都不會閃**。
換新版本時標記會回來，所以要再點一次那個 `.bat`。

## 你的密碼會怎麼被處理

**伺服器永遠看不到你的公司密碼。** 這不是「我們承諾不看」，是架構上拿不到：

- 密碼只存在你電腦的 `%APPDATA%\EasyFlowBridge\config.json`
- 存之前用 **Windows 內建的 DPAPI** 加密，綁「這台電腦 + 這個 Windows 帳號」。檔案複製到別台電腦解不開
- 網站送過來的只有「要填什麼」（假別、日期、原因）＋一段簽章，**裡面沒有任何密碼**
- 換電腦或換 Windows 帳號 → 解不開 → 要重新設定（這是刻意的）

一句話：**伺服器負責「填什麼」，這支程式負責「我是誰、怎麼登入」。** 兩件事不碰頭。

### 授權碼要當密碼看

授權碼同時是「你的頻道名來源」和「簽章金鑰」。拿到它的人可以對你的橋下指令（也就是在你電腦上填單，但**還是不能送出**）。

不要外流。真的流出去了就到網站上換一組新的，舊的立刻失效。

## 給維護者

### 跑起來

```bash
npm install
npm run setup     # 首次設定
npm start         # 啟動
```

### 檔案

| 檔案 | 做什麼 |
|---|---|
| `開始使用.bat` | 第一次的入口：清掉下載標記（`.bat` 不會被 Smart App Control 擋），再叫下面那支 |
| `EasyFlow_bridge.vbs` | 真正的啟動器：把 node 隱藏啟動，第一次順手建桌面捷徑。檔名刻意用 ASCII —— `.bat` 在 Big5 codepage 下沒辦法可靠地引用中文檔名 |
| `app.mjs` | 視窗介面版：開一個只聽 127.0.0.1 的小伺服器，用 Edge 的 `--app` 模式開視窗 |
| `ui.html` | 介面本體（單檔，樣式和 JS 都內嵌） |
| `bridge.mjs` | 命令列版（mprocs／開發用），沒有視窗 |
| `core.mjs` | 橋接核心：連 Realtime、驗簽章、分派工作。上面兩種入口共用 |
| `easyflow.mjs` | 所有 EasyFlow 的瀏覽器操作（選擇器、等待時間都在這） |
| `config.mjs` | 設定讀寫 + DPAPI 加解密 |
| `verify.mjs` | 設定的檢查步驟，CLI 和視窗共用 |
| `setup.mjs` | 命令列版的設定精靈 |
| `build-release.ps1` | 打包成給同事的 zip（含 portable Node） |

### 視窗是怎麼做出來的

沒有用 Electron（那要多 150MB）。`app.mjs` 在 `127.0.0.1` 開一個隨機 port 的小
伺服器吐 `ui.html`，然後用 **Edge 的 `--app=` 模式**開視窗 —— 沒有網址欄，看起來
就是一支獨立程式。我們本來就需要 Edge 來操作 EasyFlow，所以沒有多一個依賴。

**視窗關掉怎麼知道？** 不能用 spawn 出來的行程判斷：Edge/Chrome 啟動後會自己
重新 fork 一份、原本那個行程立刻結束，`exit` 事件會馬上誤觸發（踩過，症狀是程式
一啟動就自己關掉）。正確做法是看介面有沒有在跟伺服器要狀態 —— 關窗時瀏覽器會用
`sendBeacon` 打 `/bye`，那是最快最準的；另外留一個 2 分鐘的心跳逾時當後備
（視窗最小化時瀏覽器會把計時器降頻，所以不能設太短）。

### 踩過的雷（改之前先看）

**無頭瀏覽器（headless）不能用。** 無頭模式下 HRMESS 的表單頁會回一個完全空的 body：

```html
<html><head></head><body></body></html>
```

一個 `input` 都沒有。公司系統應該有擋。所以只能開看得見的視窗。

**`slowMo` 不能省。** EasyFlow 是舊的 frameset + 大量 JS，動作太快會在欄位還沒掛好時就被點到。症狀是「按鈕找不到」或「假別沒選中」。

**不能直接 goto 表單網址。** session 綁在 frameset 上，直接開會被踢「Session過期」。只能透過 banner 上的按鈕（`#tdMenu_1`）讓系統自己 createTab。

**假別不能打字。** 只能用選擇器選，打字會被擋（系統跳「假別還沒有選喔~」）。清單分 3 頁，而且查詢鈕是隱藏的，只能翻頁找。

**對話框要點框內的「×」才關得掉。** Escape 沒用，也沒有 class 帶 `close` 的元素。沒關掉的話下一顆按鈕會被遮住，點下去沒反應（症狀是 click 逾時）。

**截圖的座標系有兩套。** 欄位的 `getBoundingClientRect()` 是「frame 內座標」，但 `page.screenshot()` 的 `clip` 是「整頁座標」，中間差一個 frame 位移。直接混用會裁歪。要拿 `frameElement().boundingBox()` 當原點加回去。另外表單內外層各有捲軸，兩個都要捲到頂。

**算出 0 小時要當失敗。** 日期挑到連假時 EasyFlow 會跳「[輸入時段內不存在需要請假的時間區間]」而且時數欄留空 —— 這種單根本送不出去，不能回報成功。實測 2026/09/25、09/28 都這樣，而 09/18 同流程正常算出 8 小時。

**同一個帳號不要同時登入兩次。** 兩支橋一起跑會搶登入然後兩邊都失敗（實際踩過）。所以：程式偵測到重複會自動結束；有填好還沒送出的單時，查詢會被擋掉（再登入一次會把那張單的 session 踢掉）。

### 要加新的單種

banner 上那排按鈕還有「點名結果 / 加班調休申請 / 補刷卡申請 / 不加班原因說明」。

`easyflow.mjs` 的 `FORMS` 就是為這個留的，加一個 entry 就好。但那幾個的 menu id 我**只推測**是 `#tdMenu_2`…`#tdMenu_5`，**還沒實際點過**，加之前先開瀏覽器確認。

欄位 id 的規律：請假單是 `ESSQJ0xx_txt`（輸入框）、`ESSQJ0xx_btn_icon`（旁邊的選擇器按鈕）。其他單應該是不同前綴，要自己 dump 一次。
